# Overall DDC
The purpose of a Digital Down Converter (DDC) is to take a received high-frequency signal and convert it back down to a low-frequency signal. Because low-frequency data is originally transmitted using a high-frequency carrier wave for convenience, the DDC process reverses this so the original low-frequency information can be isolated.

To process the signal, the receiver multiplies the incoming high-frequency signal with a locally generated signal inside a mixer, which splits the signal into high-frequency and low-frequency components. Next, a lowpass filter removes the unwanted high-frequency part, leaving only the low-frequency signal. Finally, the signal is sent through a decimator to reduce its sampling rate.

## Goal
The goal is to convert a high-frequency real intermediate frequency (IF) signal into a complex baseband signal (I/Q data) by removing the high-frequency carrier wave.

$$
a(t) \cos (\omega_ct + \phi(t)) \longrightarrow a(t)e^{j\phi(t)} = a(t)\cos(\phi(t))+ja(t)\sin(\phi(t))
$$

# DDS
The Direct Digital Synthesizer (DDS) module acts as a digitally controlled sine and cosine wave generator. It converts a fixed clock source into variable-frequency quadrature waveforms using a phase accumulator and a pre-calculated Sine Look-Up Table (LUT).

## Core Architecture
* **Phase Accumulator (`phase_acc`):** A 32-bit register (`PHASE_ACC_W = 32`) that increments by the Frequency Tuning Word (`ftw`) on every clock cycle (`clk`). The value of `ftw` directly determines the output frequency.
* **Phase Offset / Initial Phase (`init_phase`):** Sets the starting phase state during an asynchronous reset (`rst_n`).
* **Look-Up Table (`lut_rom`):** A $1024$-entry (`LUT_ADDR_W = 10`), 12-bit wide (`LUT_OUT_W = 12`) ROM holding pre-computed sine values ranging across $[-\pi, \pi)$.

## Index & Output Generation
* **Sine Index (`k_s`):** Converts the current 32-bit phase accumulator value (`p_n`) into a 10-bit LUT address.
* **Cosine Index (`k_c`):** Adds a $90^\circ$ ($\pi/2$) phase offset to `p_n` by adding `1'b1 << (PHASE_ACC_W - 2)` before slicing the top 10 bits for the LUT address.
* **Outputs (`dds_sin`, `dds_cos`):** Registered 12-bit signed digital wave outputs fetched directly from `lut_rom[k_s]` and `lut_rom[k_c]`.



# Mixer

The Mixer module multiplies the incoming single-channel radio signal by the quadrature signals generated by the DDS. This operation translates the high-frequency passband signal down to baseband ($0\text{ Hz}$), producing two separate channels: In-phase ($I$) and Quadrature ($Q$).

## Module Signals & Parameters
* **`IN_W` (12 bits):** Width of the signed input data (`adc_data`) and DDS reference waves (`dds_cos`, `dds_sin`).
* **`OUT_W` (24 bits):** Width of the signed output channels (`i_out`, `q_out`) to prevent arithmetic overflow during full 12-bit $\times$ 12-bit multiplication.
* **`adc_data`:** Raw input signal from the Analog-to-Digital Converter.
* **`dds_cos` / `dds_sin`:** Local Oscillator reference waves generated by the DDS module.

## Mathematical Operation in Code
On every rising edge of `clk` (when reset `rst_n` is inactive), the module calculates:
* **$I$-Branch Output (`i_out`):** `adc_data * dds_cos` $\longrightarrow$ extracts $I(t)$ baseband component + high-frequency $2\omega_c$ sum term.
* **$Q$-Branch Output (`q_out`):** `adc_data * dds_sin` $\longrightarrow$ extracts $Q(t)$ baseband component + high-frequency $2\omega_c$ sum term.

$I$-branch

$$
\begin{aligned}
a(t) \cos (\omega_ct + \phi(t)) (\cos \omega_ct) &= a(t) \frac{1}{2}(\cos(\omega_ct+\phi(t)-\omega_ct) + \cos(\omega_ct+\phi(t)+\omega_ct)) \\
                                                 &= \frac{1}{2} (a(t) \cos(\phi (t)) + a(t) \cos (2\omega_ct+\phi(t))) \\
\end{aligned}
$$

$Q$-branch

$$
\begin{aligned}
a(t) \cos (\omega_ct + \phi(t)) (\sin \omega_ct) &= a(t) \frac{1}{2}(\sin(\omega_ct+\phi(t)+\omega_ct) - \sin(\omega_ct+\phi(t)-\omega_ct)) \\
                                                 &= \frac{1}{2}(a(t)\sin(2\omega_ct+\phi(t)) - a(t)\sin(\phi(t)))\\
\end{aligned}
$$



# FIR Filter
The FIR filter removes high-frequency $2\omega_c$ sum-products generated by the mixer, leaving only the low-frequency baseband components. This module implements a 32-tap transposed/cascaded FIR architecture.

## Module Parameters & Signals
* **`DATA_W` (12 bits):** Bit-width of incoming signal samples (`i_data`).
* **`COEFF_W` (12 bits):** Bit-width of the pre-calculated filter coefficients (`i_coeffs`).
* **`CAS_W` (32 bits):** Bit-width of the cascade accumulator to prevent overflow during additions.
* **`TAPS` (32):** Total number of filter taps/stages.

## MAC (Multiply-Accumulate)
The `mac_fir` module is the fundamental building block of the FIR filter. It handles the two core operations of digital filtering: signed multiplication and accumulation.

### Processing Pipeline
1. **Stage 1 (Multiplication):** Multiplies 12-bit input data (`i_data`) with its 12-bit coefficient (`i_coeff`) to produce a 24-bit product (`r_mult_res`).
2. **Pipeline Synchronization:** Registers the incoming cascade sum (`i_cascade_in_d1`) to align data timing with the multiplier output.
3. **Stage 2 (Accumulation):** Adds the current multiplication product (`r_mult_res`) to the synchronized cascade sum from the previous stage to generate `o_cascade_out`.



# Decimator
The decimator module downsamples the filtered baseband signal by a factor of $M$, reducing the sample rate from $F_s$ to $F_s/M$. This lowers the data throughput to the required bandwidth, saving processing power and memory for downstream baseband processing.

## Core Operations
* **Sample Rate Reduction:** Retains 1 out of every $M$ incoming samples from the FIR filter and discards the intermediate $M-1$ samples. Here we gave $M = 10$. We cannot take any values larger than $M=10$ due to Nyquist sampling theorem, because then the sampling rate will be less than twice the stopband and cause aliasing.
* **Clock & Valid Control:** Generates a output data valid pulse (`valid_out`) every $M$ clock cycles to signal when a new downsampled sample is available.

# DDC Top Level
The `ddc_top` module integrates all sub-components—DDS, Mixer, FIR Filters, and Polyphase Decimators—into a unified Digital Down Converter pipeline. It processes a single 12-bit IF input signal sampled at $100\text{ MHz}$ and translates it down to 10 MSPS complex baseband ($I/Q$) outputs.

## System Parameters
* **`F_SAMP` ($100\text{ MHz}$):** Input system sampling rate.
* **`F_CARR` ($20\text{ MHz}$):** Target carrier/NCO center frequency.
* **`FTW`:** Frequency Tuning Word calculated automatically as $FTW = \frac{F_{carr}}{F_{samp}} \times 2^{32}$.
* **`DEC_FACTOR` ($10$):** Decimation factor, lowering output sample rate from $100\text{ MHz} \longrightarrow 10\text{ MHz}$.

## Sub-Module Interconnects
1. **DDS Generator (`u_dds`):** Synthesizes 12-bit quadrature reference signals (`dds_sin`, `dds_cos`) tuned to $20\text{ MHz}$.
2. **Quadrature Mixer (`u_mixer`):** Multiplies input `i_if_signal` by `dds_cos` and `dds_sin` to create 24-bit $I/Q$ intermediate paths (`i_mix`, `q_mix`).
3. **Low-Pass Filtering (`u_fir_i`, `u_fir_q`):** Two parallel 32-tap FIR filter instances filter high-frequency mixing image products.
4. **Decimation (`u_decimator_i`, `u_decimator_q`):** Downsamples filtered $I/Q$ channels by $10\times$ and asserts `o_data_valid` every 10 clock cycles.

## Verification & Testbench (`ddc_top_tb`)
The `ddc_top_tb` module serves as the simulation environment to verify top-level DDC functional accuracy. It generates real-time synthetic input signals, applies pre-computed MATLAB filter coefficients, and logs output data for external analysis.

### Key Features & Test Setup
* **Clock & Stimulus Generation:** Generates a $100\text{ MHz}$ master system clock (`clk`) and constructs a quantized 12-bit input signal (`i_if_signal`) combining a target carrier wave ($19\text{ MHz}$) and an interference tone ($35\text{ MHz}$).
* **MATLAB Filter Coefficients:** The 33-tap FIR filter coefficients (`fir_coeffs`) and 23-tap Decimator filter coefficients (`deci_coeffs`) were designed and generated using **MATLAB's `filterDesigner`** to ensure sharp out-of-band rejection.
* **Data Logging & Python Post-Processing:** Writes decimated $I/Q$ baseband outputs (`o_i_data`, `o_q_data`) to `ddc_iq_output.txt` on every `o_data_valid` strobe pulse for downstream Python FFT and spectral verification.
